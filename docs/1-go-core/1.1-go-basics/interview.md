# Go 基础语法面试指南

> 本指南汇总 Go 基础语法模块的高频面试题，按考察频率排序。每道题标注难度和出现频率，帮助你高效准备面试。

## 🔥🔥🔥 最高频（几乎必考）

### Q1: Slice 的扩容机制

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥 | **关联**：[数组与切片](./09-slice.md)

**标准答案**：

切片底层是一个包含指针、长度、容量的结构体（SliceHeader）。当 append 导致长度超过容量时触发扩容：

- Go 1.18+：旧容量 < 256 时翻倍；>= 256 时按 `oldcap + (oldcap + 3*256) / 4` 增长（约 1.25x~2x 平滑过渡）
- 最终容量会经过内存对齐调整

**深入追问**：
- 扩容后底层数组地址会变吗？（会，分配新数组并拷贝）
- 两个切片共享底层数组时，一个扩容会影响另一个吗？（不会，扩容后指向新数组）

### Q2: defer 的执行顺序

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥 | **关联**：[函数](./06-functions.md)

**标准答案**：

```go
func f() int {
    defer fmt.Println("defer 1") // 第三个执行
    defer fmt.Println("defer 2") // 第二个执行
    defer fmt.Println("defer 3") // 第一个执行
    return 0
}
```

1. defer 按 LIFO（后进先出）顺序执行
2. defer 在 return 之后、函数真正返回之前执行
3. defer 的参数在声明时求值（不是执行时）
4. defer 可以修改命名返回值

**经典陷阱题**：

```go
func f() (result int) {
    defer func() { result++ }()
    return 0
}
// 返回 1，不是 0！
// 执行顺序：result = 0 → defer: result++ → 返回 result(1)
```

### Q3: Go 是值传递还是引用传递？

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥 | **关联**：[指针](./11-pointer.md)

**标准答案**：

**Go 中一切都是值传递**，没有引用传递。

- 基本类型：拷贝值
- 指针：拷贝指针的值（内存地址）
- slice：拷贝 SliceHeader（指针+长度+容量），底层数组共享
- map：拷贝指向 hmap 的指针
- channel：拷贝指向 hchan 的指针

**追问**：slice 传参后 append 会影响原切片吗？
- 不扩容时：修改元素会影响（共享底层数组）
- 扩容时：不会影响（新底层数组）
- append 后的长度变化不会反映到原切片（长度是 header 的一部分，被拷贝了）

### Q4: 值接收者和指针接收者的区别

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥 | **关联**：[结构体与方法](./08-struct-method.md)

**标准答案**：

| 特性 | 值接收者 | 指针接收者 |
|------|---------|-----------|
| 修改原值 | ❌ 操作副本 | ✅ 操作原值 |
| 方法集 | T 和 *T 都包含 | 仅 *T 包含 |
| 接口实现 | T 和 *T 都实现 | 仅 *T 实现 |
| 适用场景 | 小型不可变类型 | 需要修改/大型结构体 |

**选择原则**：如果不确定，用指针接收者。如果某个方法用了指针接收者，其他方法也应该用（一致性）。

### Q5: new 和 make 的区别

**难度**：⭐⭐ | **频率**：🔥🔥🔥 | **关联**：[指针](./11-pointer.md)

**标准答案**：

- `new(T)` 分配零值内存，返回 `*T`，适用于任意类型
- `make(T)` 初始化内部数据结构，返回 `T`，仅适用于 slice/map/channel
- `new([]int)` 返回 `*[]int`（指向 nil 切片的指针），`make([]int, 0)` 返回已初始化的空切片

## 🔥🔥 高频（经常考）

### Q6: Map 为什么并发不安全？

**难度**：⭐⭐⭐ | **频率**：🔥🔥 | **关联**：[Map](./10-map.md)

**标准答案**：

Go 的 map 没有内置锁，并发读写会触发 `fatal error: concurrent map writes`（注意：这是 fatal error，不是 panic，无法 recover）。Go 团队认为大多数 map 使用场景不需要并发安全，加锁会影响所有场景的性能。

**解决方案**：
1. `sync.Mutex` / `sync.RWMutex`（通用方案）
2. `sync.Map`（读多写少场景）
3. 分片锁（高并发场景）

### Q7: 字符串拼接的性能对比

**难度**：⭐⭐ | **频率**：🔥🔥 | **关联**：[字符串处理](./13-string.md)

**标准答案**：

性能从高到低：`strings.Builder` > `bytes.Buffer` > `strings.Join` > `fmt.Sprintf` > `+`

`strings.Builder` 最优是因为：
1. 内部使用 `[]byte`，避免字符串不可变导致的重复分配
2. `String()` 方法通过 unsafe 直接转换，零拷贝
3. 可以通过 `Grow()` 预分配容量

### Q8: 错误处理：errors.Is 和 errors.As 的区别

**难度**：⭐⭐⭐ | **频率**：🔥🔥 | **关联**：[错误处理](./07-error-handling.md)

**标准答案**：

- `errors.Is(err, target)` — 沿错误链查找是否包含特定**错误值**（值比较）
- `errors.As(err, &target)` — 沿错误链查找是否包含特定**错误类型**（类型匹配）
- 两者都会递归解包 `%w` 包装的错误链

---

### Q9: for-range 的陷阱

**难度**：⭐⭐⭐ | **频率**：🔥🔥 | **关联**：[控制流](./05-control-flow.md)

**标准答案**：

1. **值拷贝**：`for _, v := range slice` 中 `v` 是元素的拷贝，修改 `v` 不影响原切片
2. **循环变量复用**（Go 1.22 之前）：所有迭代共享同一个循环变量，闭包捕获会出问题
3. **map 遍历无序**：每次遍历顺序可能不同
4. **遍历中修改**：遍历 slice 时 append 不会影响遍历范围（遍历前已确定长度）

## 🔥 中频（偶尔考）

### Q10: iota 的工作原理

**难度**：⭐⭐ | **频率**：🔥 | **关联**：[变量、常量与作用域](./03-variables.md)

**标准答案**：

`iota` 在每个 `const` 块中从 0 开始，每新增一行自增 1。常用于枚举和位运算权限定义。

---

### Q11: Go 的零值机制

**难度**：⭐⭐ | **频率**：🔥 | **关联**：[数据类型](./02-data-types.md)

**标准答案**：

Go 的变量声明后自动初始化为零值：数值类型为 0，布尔为 false，字符串为 ""，指针/slice/map/channel/interface/func 为 nil。零值的好处是声明即可用，减少 null 引用错误。

1. **画图说明**：slice 扩容、defer 栈等问题，画图比口述更清晰

4. **关联知识**：将基础知识与实际项目经验关联，展示应用能力
